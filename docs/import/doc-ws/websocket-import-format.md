# Формат файла импорта сообщений WebSocket

Файл `websocket-example-import.json` — пример JSON-файла для импорта примеров сообщений (example frames) в WebSocket-доку Docpoint.

## Точки входа

**Импорт сокета целиком** — пункт «Импорт → WebSocket (JSON)» в проводнике платформы (`CatalogExplorer`). Что произойдёт, решает `websocket.id`: сокета с таким id нет — он создаётся в открытом каталоге, есть — файл дописывается в него (см. [Обновление сокета из файла](#обновление-сокета-из-файла)). Блок `websocket` здесь **обязателен**, а `messages` можно опустить — получится пустой сокет.

**Импорт сообщений в открытый сокет** — добавляет `messages` в сокет, открытый на странице `DocWsShowPage`; блок `websocket` в этом случае справочный. Мутация есть в `useWebsocketMessages` (`importMessagesAsync`), кнопки в интерфейсе пока нет.

## Общая структура

```json
{
  "version": 1,
  "websocket": { ... },   // необязательно, справочная информация
  "messages": [ ... ]     // обязательно, список сообщений для импорта
}
```

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `version` | number | да | Версия формата файла (сейчас всегда `1`) |
| `websocket` | object | зависит | Описание сокета. Обязателен при импорте в каталог — из него создаётся узел-сокет. При импорте в уже открытый сокет справочный и не используется |
| `messages` | Message[] | зависит | Список импортируемых сообщений. Обязателен и непуст при импорте в открытый сокет; при импорте в каталог можно опустить |

## `websocket` — описание сокета

```json
"websocket": {
  "id": "c1d0a7e4-58b3-4a2f-9d61-7b0c3e5a2f18",
  "name": "Kline Stream",
  "url": "wss://example.com/ws"
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | Ключ сокета. Импорт ищет сокет с этим id и дописывает файл в него; если такого нет — заводит его под этим же id. Без `id` каждый импорт создаёт новый сокет |
| `name` | string | Название сокета. Обязательно при импорте в каталог, иначе справочное |
| `url` | string | URL сокета. Обязателен при импорте в каталог, иначе справочный |

Описания у сокета нет — у узлов дерева его не бывает, — поэтому поле `desc`
рядом с `name` просто игнорируется. Описание есть у каждого сообщения.

Годится любая строка, лишь бы она была уникальной в пределах установки:
uuid, `kline-stream`, `binance/ws`. Смысла внутри id нет — приложение только
сравнивает его с id документов, которые уже есть. Если id занят документом
другого вида, импорт остановится.

## `messages` — список сообщений

Каждый элемент — одно сохранённое сообщение-пример, повторяет форму `CreateWebsocketMessageDTO` без `websocket_id` (он подставляется автоматически на месте импорта).

```json
{
  "name": "Subscribe",
  "desc": "Подписка на kline-стрим",
  "payload": "{ \"op\": \"subscribe\", \"id\": \"init\", \"streams\": \"kline.exchange.symbol.interval\" }"
}
```

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `name` | string | да | Название сообщения, отображается в сайдбаре «Examples» |
| `desc` | string | нет | Описание назначения сообщения. По умолчанию — пустая строка |
| `payload` | string | да | Тело сообщения. Хранится и передаётся как строка — JSON внутри экранируется (`\"`, `\n`), как в примере выше |

## Обновление сокета из файла

Импорт один и тот же, разница — в `websocket.id`.

- **Сокета с таким id нет** — он создаётся в открытом каталоге под этим же id.
- **Есть** — файл дописывается в него: адрес берётся из файла, сообщения
  опознаются **по имени**. Одноимённое перезаписывается, новое добавляется.

Сообщения, которых в файле нет, остаются: файл описывает то, что в нём
написано, а не весь сокет целиком — примеры кадров заводят и руками. Имя сокета
и его место в дереве файл тоже не меняет.

Два сообщения с одинаковым `name` в одном файле — ошибка: по имени они и
опознаются, и непонятно, какое из описаний настоящее.

## Чек-лист перед импортом

- [ ] Если файл должен обновлять уже заведённый сокет — в `websocket.id` стоит его id
- [ ] JSON валиден (используйте линтер или `jq .`)
- [ ] `version` равен `1`
- [ ] У каждого сообщения есть `name` и `payload`
- [ ] `payload` — это **строка**, а не объект. JSON внутри экранирован
- [ ] Для импорта в каталог: заполнены `websocket.name` и `websocket.url`
- [ ] Для импорта в открытый сокет: `messages` непуст, а на странице WebSocket открыт нужный сокет

## Минимальный шаблон

Для импорта в каталог — с блоком `websocket`:

```json
{
  "version": 1,
  "websocket": {
    "id": "my-socket",
    "name": "My Socket",
    "url": "wss://example.com/ws"
  },
  "messages": [
    {
      "name": "Ping",
      "desc": "",
      "payload": "{ \"op\": \"ping\" }"
    }
  ]
}
```

Для импорта в уже открытый сокет достаточно одних сообщений:

```json
{
  "version": 1,
  "messages": [
    {
      "name": "Ping",
      "desc": "",
      "payload": "{ \"op\": \"ping\" }"
    }
  ]
}
```

Полный пример доступен в [websocket-example-import.json](websocket-example-import.json).
