# Формат экспорта платформы (zip-архив)

Экспорт платформы — это `.zip`-архив со всем деревом документации, окружениями и загруженными файлами. Импорт всегда заводит **новую** платформу со свежими id: существующие платформы им не затрагиваются, и один и тот же архив можно импортировать сколько угодно раз.

## Точки входа

- **Экспортировать** — пункт меню действий платформы в сайдбаре (значок «⋮» на карточке платформы). Открывает системный диалог сохранения `.zip`.
- **Импортировать из zip** — кнопка под списком платформ в сайдбаре, рядом с «+ Платформа». Открывает системный диалог выбора файла и сразу создаёт новую платформу из выбранного архива.

## Структура архива

```
platform.zip
├── manifest.json
└── files/
    └── <id узла>/<имя файла>
```

`manifest.json` — единый JSON-документ с платформой, окружениями и деревом узлов. Байты загруженных файлов лежат рядом отдельными записями архива, а не внутри манифеста.

```jsonc
{
  "version": 1,
  "platform": { "name": "...", "desc": "..." },
  "environments": [ ... ],
  "nodes": [ ... ]
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `version` | number | Версия формата (сейчас всегда `1`) |
| `platform` | object | Имя и описание платформы |
| `environments` | Environment[] | Окружения платформы |
| `nodes` | Node[] | Всё дерево документации одним списком |

### Id внутри архива

`id` каждого узла и каждой ERD-таблицы в манифесте — это их реальный id **на момент экспорта**. Внутри файла он служит только ключом для связей: `parentId` узла и `fromEntity`/`toEntity` ERD-связи ссылаются на такие id. При импорте всё получает полностью новые id; исходные из архива нигде не переиспользуются.

## `environments[]` — окружения

```jsonc
{
  "env": "prod",
  "label": "Production",
  "baseUrl": "https://api.example.com",
  "prefix": "/v1",
  "variables": [ { "id": "...", "name": "TOKEN", "value": "...", "isSecret": true } ],
  "auth": { ... },
  "proxy": { ... }
}
```

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `env` | string | да | Код окружения |
| `label` | string | да | Название окружения |
| `baseUrl` | string | да | Базовый URL |
| `prefix` | string | да | Общий префикс окружения |
| `variables` | Variable[] | нет | Переменные окружения |
| `auth` | object | нет | Настройки авторизации (`EnvironmentAuthDTO`), включая **живой access-токен и куки сессии** |
| `proxy` | object | нет | Настройки прокси (`EnvironmentProxyDTO`), включая пароль |

Переносится полностью, «как есть» — это перенос той же платформы, а не создание чистой копии окружения (в отличие от «Дублировать окружение», которое намеренно не копирует токен и куки сессии). Пароли, токены и куки в базе и так хранятся открытым текстом, поэтому в архиве они тоже открытым текстом — обращайтесь с файлом архива как с секретом.

---

## `nodes[]` — дерево документации

```jsonc
{
  "id": "…", "parentId": "… | null", "kind": "catalog|docApi|docWs|docErd|markdown|file",
  "name": "…",
  "content": "…",       // только markdown
  "file": { "filename": "…" },   // только file
  "docApi": { ... },    // только docApi
  "docWs": { ... },     // только docWs
  "docErd": { ... }     // только docErd
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | Id узла в архиве — только для связей `parentId` |
| `parentId` | string \| null | Id родителя в архиве; `null` — корень платформы |
| `kind` | string | Вид узла |
| `name` | string | Имя узла |

Секция с полезной нагрузкой присутствует только для своего вида узла; `catalog` — без секции.

### `markdown`

`content` — тело документа строкой.

### `file`

```jsonc
"file": { "filename": "report.pdf" }
```

Байты лежат в архиве отдельно, по пути `files/<id узла>/<filename>`.

### `docApi`

```jsonc
"docApi": {
  "prefix": "v1",
  "groups": [
    {
      "label": "Auth",
      "endpoints": [
        {
          "method": "POST", "path": "/auth/login", "name": "Login", "description": "…", "auth": false,
          "pathParams": [], "queryParams": [], "body": { ... }, "bodyFields": [ ... ],
          "responses": { ... },
          "requests": [ { "name": "…", "bodyMode": "fields", "body": "…", "headers": [...], "values": [...] } ]
        }
      ]
    }
  ]
}
```

Форма групп и эндпоинтов совпадает с [форматом ручного JSON-импорта doc-api](../doc-api/doc-api-import-format.md), плюс у каждого эндпоинта дополнительно переносятся сохранённые наборы «Try it» (`requests`) — обычный экспорт одного документа (`Экспорт` в контекстном меню doc-api) их не переносит, а экспорт платформы переносит.

### `docWs`

```jsonc
"docWs": {
  "url": "wss://example.com/ws",
  "messages": [ { "name": "Subscribe", "payload": "…", "desc": "…" } ]
}
```

### `docErd`

```jsonc
"docErd": {
  "entities": [
    { "id": "…", "name": "users", "desc": "…", "fields": [ ... ], "posX": 40, "posY": 80 }
  ],
  "relations": [
    { "id": "…", "fromEntity": "…", "fromField": "id", "toEntity": "…", "toField": "user_id" }
  ],
  "frames": [
    { "id": "…", "title": "Биллинг", "x": 100, "y": 100, "w": 400, "h": 300 }
  ]
}
```

В отличие от [ручного JSON-импорта ERD](../doc-erd/doc-erd-import-format.md), который не хранит координаты и перекладывает таблицы сеткой, экспорт платформы переносит `posX`/`posY` как есть — расположение таблиц на холсте сохраняется точно. `null` у обоих координат означает «таблицу ещё не размещали»: после импорта холст разложит её автолейаутом, как и для только что созданной таблицы, а не поставит в `(0, 0)`.

`frames` — области холста: подписанные прямоугольники, которыми таблицы сгруппированы. Таблицы в них не перечислены: области принадлежит то, что лежит внутри её границ, и после переноса координат группировка восстанавливается сама. Поле появилось позже таблиц и связей — в архивах, снятых до него, его нет, и диаграмма импортируется просто без областей.

## Что переносится лосслесс, а что — нет

Лосслесс: имена и структура дерева, содержимое markdown, полная схема, позиции и области ERD (включая ещё не размещённые таблицы), doc-api эндпоинты вместе с сохранёнными наборами «Try it», сообщения websocket, окружения целиком (переменные, авторизация с токеном и куками сессии, прокси), байты загруженных файлов (побайтово идентичны).

Не переносится: `createdAt`/`updatedAt` узлов (при импорте проставляются заново — платформа новая); обзорный markdown-текст doc-api узла — на сегодня ни один код-путь его не записывает, поле не используемое.
